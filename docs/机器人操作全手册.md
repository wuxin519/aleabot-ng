## 一、当前部署事实

### 1.1 三服务架构

三个服务均为 systemd 托管、开机自启，全部运行在服务器 `<服务器IP>` 上。

| 服务 | 作用 | 端口 | 目录 |
|------|------|------|------|
| `napcat` | QQ 登录 + OneBot 11 正向 WS 服务器 | 6099 (WebUI) / **3001** (OneBot WS) | `<NapCat目录>/app/runtime` |
| `aleabot` | 骰点引擎 + 网页管理后台 | **8787** | `<安装目录>` |
| `qr-server` | 实时二维码页（重登 QQ 时用） | **6098** | `<NapCat目录>/qr-server.js` |

### 1.2 访问地址

| 用途 | 地址 |
|------|------|
| **网页管理后台** | `http://<服务器IP>:8787/` |
| **实时二维码（重登用）** | `http://<服务器IP>:6098/` |
| NapCat WebUI | `http://<服务器IP>:6099/webui?token=<见下>` |

> NapCat WebUI token 会随运行目录变化**重新生成**，最新值读
> `<NapCat目录>/app/runtime/config/webui.json` 的 `token` 字段。

### 1.3 账号信息

| 项目 | 值 |
|------|-----|
| 机器人 QQ | `3322540068`（昵称「叭叭叭」） |
| 所在群 1 | `1048322583`（维也纳金色大厅） |
| 所在群 2 | `194646405`（蔷薇猛虎皆个性2） |
| 好友数 | 6（含「无心」940129350 / 751988899） |
| 平台状态 | QQ 在线；KOOK 未启用 |

### 1.4 连接方向（易搞反，务必记牢）

```
NapCat（WebSocket 服务器，监听 0.0.0.0:3001）
        ▲
        │  主动连接 ws://127.0.0.1:3001
        │
AleaBot（WebSocket 客户端）
```

- NapCat 侧配置项是 **`websocketServers`**（正向 WS 服务器）
- AleaBot 侧是 `ONEBOT_WS_URL=ws://127.0.0.1:3001`
- **两侧模式必须匹配**，一边改另一边也要跟着改。

## 二、玩家指令总表

所有指令以 **`.`** 开头（前缀可在群内用 `.set prefix` 修改，见第九章）。

> **中英文句号等价**：中文输入法打出的全角句号 **`。`** 与英文句点 **`.`** 完全等效，
> `。r 3d6` ≡ `.r 3d6`、`。st力量88` ≡ `.st 力量 88`，其余所有指令同理。
> 只要群前缀是 `.`（默认）或 `。`，两种写法都识别。
> 注意句号必须在**句首**才会被当作指令前缀，句中的「。」只是普通标点。

## 三、掷骰表达式完整语法

### 3.1 基础形式

| 写法 | 含义 | 结果示例 |
|------|------|----------|
| `3d6` | 3 个 6 面骰求和 | `3d6[4+3+5] = 12` |
| `d6` / `D6` | 省略数量 = 1 个 | `1d6[5] = 5` |
| `d` / `2d` | **省略面数** = 用群默认骰面（默认 100，`.set defaultDice` 可改） | `2d[43+17] = 60` |
| `3d6+2` | 加常量 | `3d6[4+3+5] +2 = 14` |
| `2d8-1` | 减常量 | `2d8[6+3] -1 = 8` |
| `3d6+1d4` | **多组骰子混合** | `3d6[2+4+1] 1d4[3] = 10` |
| `1d20+2-1` | 加减混合 | 按从左到右求和 |

### 3.2 保留 / 丢弃（keep / drop）

后缀语法：`k` / `kh` / `kl` / `dh` / `dl`，后面跟**可选数字**（省略则为 1）。

| 后缀 | 含义 | 示例 | 效果 |
|------|------|------|------|
| `k` / `kh` | 保留**最高** N 个 | `4d6k3` | 4d6 取最高的 3 个（D&D 属性） |
| `kl` | 保留**最低** N 个 | `2d20kl1` | 劣势（取低） |
| `dh` | 丢弃**最高** N 个 | `4d6dh1` | 去掉最高 1 个 |
| `dl` | 丢弃**最低** N 个 | `4d6dl1` | 去掉最低 1 个（等价 4d6k3） |

> ⚠️ `4d6k3` 与 `4d6dl1` **结果数学上等价**（都是留 3 个最高的），但输出提示文字不同。

### 3.3 常见跑团用法

| 用途 | 表达式 |
|------|--------|
| D&D 5e 属性生成（标准） | `.r 4d6k3` |
| D&D 优势（标准写法） | `.r 2d20kh1` |
| D&D 优势（中文写法） | `.r d20优势` |
| D&D 劣势（中文写法） | `.r d劣势` |
| 攻击伤害 | `.r 1d8+3` |
| 火球术（8d6） | `.r 8d6` |
| 疗伤术 | `.r 2d8+2` |
| COC 幸运检定 | `.r 1d100<=55` |
| 纯随机 1-100 | `.r` |

> **中文优势/劣势规则**：必须带 `d` 前缀（如 `d20优势`），单独写「优势」两个字不会被转换（避免误伤聊天内容）。省略面数时用群默认骰面；写了数量（如 `2d20优势`）固定按 2 骰取 1。

### 3.4 紧贴写法与多轮掷骰（v1.2 新增）

**紧贴写法**：动词与参数之间**不需要空格**，与主流骰娘习惯一致：

| 紧贴写法 | 等价于 |
|----------|--------|
| `.r3d100` | `.r 3d100` |
| `.r3#2d50` | `.r 3#2d50` |
| `.ra侦查60` | `.ra 侦查 60` |
| `.st力量88` | `.st 力量 88` |

**多轮掷骰**：`N#表达式` = 把同一表达式掷 N 次（上限 20），并给出合计：

```
🎲 【张三】掷骰3次 (合计 132):
1. 2d50=44  2d50[22+22] = 44
2. 2d50=44  2d50[22+22] = 44
3. 2d50=44  2d50[22+22] = 44
```

### 3.5 特殊骰法：Fate / WoD / 双十字（v1.2 新增）

| 写法 | 规则 | 输出示例 |
|------|------|----------|
| `f` / `4df` | **Fate 命运骰**：4 枚 [-1/0/+1] 求和 | `f=[+0--] = -1` |
| `XaY` | **WoD 无限骰**：X 个 d10，`≥Y` 触发加骰、`≥8` 算成功，加骰滚到没有为止 | `5a6=成功3/11 轮数:5 {<8*>,4,<6>,<7>,1}…` |
| `XaYkN` / `XaYmZ` | 同上，指定成功线 N / 面数 Z | `10a6k4m9` |
| `XaYqN` | 成功判定反转为 `≤N` | `5a6q3` |
| `XcY` | **双十字骰**：X 个 d10，`≥Y` 暴击续轮；出目 = 暴击轮数×10 + 末轮最大点 | `4c3=出目121/35 轮数:13 {<9>,<6>,<5>,<10>}…` |
| `XcYmZ` | 同上，指定面数 Z | `4c3m7` |

> 标记说明：`<v>` = 触发加骰/暴击；`v*` = 触发成功；`<v*>` = 两者都触发。
> 续轮上限 30 轮；明细最多展示前 6 轮，超出显示 `…(+N轮)`，防止刷屏。

### 3.6 裸奖励/惩罚骰与暗骰（v1.2 新增）

| 指令 | 作用 | 输出示例 |
|------|------|----------|
| `.r b` / `.r b3` | 裸奖励骰：不做技能检定，直接掷一次奖励骰 D100（1-5 个额外十位骰） | `b3 = 44 / 奖励骰×3: 十位[40/40/40/40] 个位[4] → 候选(44 44 44 44) 取最小 → 44` |
| `.r p` / `.r p2` | 裸惩罚骰（取最大） | 同上，`取最大` |
| `.rh <表达式>` | **暗骰**：群里只发「🎲 【张三】正在暗中掷骰…」，结果私聊给掷骰者 | 私聊收到 `🎲 【张三】1d20 = 9` |

> 暗骰只在群里有意义，私聊发 `.rh` 会被提示直接掷即可。

### 3.7 输出格式说明

**掷骰输出**（两行）：

```
🎲 【张三】3d6+2 = 14
3d6[4+3+5] +2 = 14
```

- 第 1 行：发言人 + 原表达式 + 最终结果
- 第 2 行：**明细**（原始点数 + 保留规则 + 常量）
- 带 keep 规则时，明细会同时显示全量与保留量：

```

4d6[6+5+2+1] 取高3→[6+5+2] = 13
```

## 四、COC 检定（.ra）详解

### 4.1 三种用法

```
.ra 侦查 60      ① 指定技能名 + 目标值
.ra 侦查         ② 只写技能名 → 自动读你的角色卡
.ra 60           ③ 只写数字  → 直接以 60 为目标检定
```

**② 的读取逻辑**：从你的角色卡里查 `侦查` 或 `技能_侦查` 字段；
查不到时提示 `未找到技能「侦查」的目标值，请补充，如 .ra 侦查 60`。

### 4.2 输出格式

```
✅ 【张三】侦查检定: 1d100 = 23 / 60 → 困难成功
```

结构：`成功图标 + 发言人 + 技能名 + 检定 + 掷出值 / 目标值 → 成功等级`

- ✅ = 成功（大成功 / 极难成功 / 困难成功 / 成功）
- ❌ = 失败（失败 / 大失败）

### 4.3 成功等级判定规则（COC 7 版）

设目标值为 `T`，掷出值为 `R`（1–100）：

| 等级 | 判定条件 | 说明 |
|------|----------|------|
| **大成功** | `R = 1` | 无论 T 多少 |
| **极难成功** | `R ≤ ⌊T/5⌋` | 1/5 以内 |
| **困难成功** | `R ≤ ⌊T/2⌋` | 1/2 以内 |
| **成功** | `R ≤ T` | 常规成功 |
| **失败** | `R > T` | |
| **大失败** | `T < 50` 时 `R ≥ 96`；`T ≥ 50` 时 `R = 100` | |

**示例**（T = 60）：

| 掷出 | 等级 |
|------|------|
| 1 | 大成功 |
| 2–12 | 极难成功（60/5 = 12） |
| 13–30 | 困难成功（60/2 = 30） |
| 31–60 | 成功 |
| 61–100 | 失败（T=60 ≥ 50，故无大失败） |

**示例**（T = 40，`T < 50`）：

| 掷出 | 等级 |
|------|------|
| 1 | 大成功 |
| 2–8 | 极难成功 |
| 9–20 | 困难成功 |
| 21–40 | 成功 |
| 41–95 | 失败 |
| **96–100** | **大失败** |

### 4.4 与 `.r 1d100<=50` 的区别

| 写法 | 输出 |
|------|------|
| `.ra 侦查 60` | `✅ 【张三】侦查检定: 1d100 = 23 / 60 → 困难成功` |
| `.r 1d100<=60` | `🎲 【张三】1d100<=60 = 23` + `1d100[23] = 23 → 困难成功` |

两者**判定规则完全一致**，只是 `.ra` 输出更简洁、且支持**自动读角色卡**。

### 4.5 理智检定 `.sc`（v1.2 新增）

```
.sc              ① 默认扣减：成功扣 1 / 失败扣 1d6
.sc 1d6          ② 只写失败扣：成功扣 1 / 失败扣 1d6
.sc 0/1d10       ③ 分别指定：成功扣 0 / 失败扣 1d10
.sc 60 1/1d6     ④ 直接指定当前 SAN（不读卡）
```

- 先掷 1d100 与卡上「理智」比较，按成功等级决定扣减
- **大成功**：理智毫发无损
- **大失败**：按失败表达式取**最大值**扣（`1d6` → 6，`2d6+1` → 13，COC 7 常用房规）
- 扣减结果**自动写回角色卡**「理智」字段

```
🎲 【张三】理智检定: 1d100 = 43 / 55 → 成功
🩸 SAN 扣减 1 = 1 → 55 → 54（-1）
```

### 4.6 对抗检定 `.rav @对手`（v1.2 新增）

```
.rav @李四 侦查          ① 双方都读各自的卡
.rav @李四 侦查 60 55    ② 直接指定我方 60 / 对方 55
```

- 双方各掷 1d100，**成功等级高者胜**（大成功 > 极难 > 困难 > 成功 > 失败）
- 同级时**骰值小者胜**（COC 对抗惯例）；完全相同则提示重掷
- 双方都失败视为僵局

```
⚔️ 张三 vs 李四「侦查」对抗
张三: 1d100 = 23 / 60 → 困难成功
李四: 1d100 = 45 / 55 → 成功
🏆 张三 胜出！
```

### 4.7 房规切换 `.setcoc`（v1.2 新增，v1.4 补全 0-5/dg）

影响 `.ra` / `.rb` / `.rp` / `.rc` / `.sc` / `.r 1d100<=x` 的大成功 / 大失败判定，**按群分别保存**。
v1.4 起编号与**主流骰娘核心官方手册完全一致**（v1.2 时 1/2 的定义与主流骰娘错位，已修正）：

| 房规 | 规则 |
|------|------|
| `0`（默认） | 出 1 大成功；目标 < 50 时出 96-100 大失败，目标 ≥ 50 时出 100 大失败（CoC7th 规则书） |
| `1` | 目标 < 50 时出 1 大成功、出 96-100 大失败；目标 ≥ 50 时出 1 大成功、出 100 大失败 |
| `2`（常用） | 出 1-5 且判定成功为大成功；出 96-100 且判定失败为大失败 |
| `3` | 出 1-5 恒大成功，出 96-100 恒大失败（大成功/大失败时无视判定结果） |
| `4` | 出 1-5 且 ≤ 成功率/10 为大成功；目标 < 50 时出 96+成功率/10 大失败，目标 ≥ 50 时出 100 |
| `5` | 出 1-2 且 ≤ 成功率/5 为大成功；目标 < 50 时出 96-100 大失败，目标 ≥ 50 时出 99-100 |
| `dg` | 骰运：出 1 或（判定成功且十位=个位）大成功；出 100 或（判定失败且十位=个位）大失败；**无困难/极难成功** |

```
.setcoc              查看当前房规与说明
.setcoc details      列出全部可用房规
.setcoc 2            切换到房规 2
.setcoc dg           切换到骰运房规
```

> ⚠️ **升级提醒**：v1.2 的房规 `1`/`2` 定义与主流骰娘不一致（当时的 1 实际是主流骰娘的 2，当时的 2 是主流骰娘的 3）。
> v1.4 已按主流骰娘官方定义修正。如果你之前在群里设过房规 1 或 2，需要重新确认是否符合预期。

### 4.8 检定增强：属性调整与难度前缀（v1.4 新增）

**属性调整**：技能名后可以带 `+`/`-` 和数值（数值本身可以是骰点表达式）：

```
.ra 侦查+10        卡上 40 → 目标 50
.ra 侦查-5         卡上 40 → 目标 35
.ra 侦查+1d4       加值 1d4（每次检定重新掷）
.ra 困难侦查+10    难度前缀 + 调整，可组合
```

**难度前缀**：要求达到指定成功等级才算通过，否则即使普通成功也算失败。

| 前缀 | 判定线 | 说明 |
|------|--------|------|
| `困难` | 目标 ÷ 2 | 必须达到「困难成功」 |
| `极难` | 目标 ÷ 5 | 必须达到「极难成功」 |
| `简易` | 目标 ÷ 2 | 同困难（宽松写法） |
| `大成功` | — | 必须掷出大成功 |

```
.ra 困难侦查       输出会标注「需困难成功」
.ra 极难侦查+10
.ra 大成功侦查
```

### 4.9 规则书检定 `.rc`（v1.4 新增）

`.ra` 走**群房规**（`.setcoc` 设置），`.rc` 强制走**规则书标准**（等价于房规 0）。
当房规设为 0 时两者等价；房规不是 0 时用 `.rc` 可以对照「严格按规则书」的结果。

```
.setcoc 2      房规改成常用房规
.ra 侦查       按房规 2 判定
.rc 侦查       按规则书判定（无视房规）
```

### 4.10 理智检定标志 `--cap` / `--half`（v1.4 新增）

| 标志 | 作用 | 对应规则 |
|------|------|---------|
| `--cap=N` | 本次理智损失上限为 N | 习惯恐怖 |
| `--half` | 本次损失减半（向下取整） | 神话淬炼（精神固化） |

两者可同时使用，顺序是**先减半、再按上限截断**：

.sc 1/1d6 --cap=3          掷出 1d6=5 → 截断为 3
.sc 1/1d6 --half           掷出 1d6=5 → 减半为 2
.sc 1/1d6 --cap=2 --half   掷出 1d6=6 → 减半为 3 → 截断为 2
```

### 4.11 技能成长 `.en` 多技能与自定义点数（v1.4 新增）

**一次成长多个技能**（相同技能不能在一���命令里重复）：

## 五、角色卡系统

### 5.1 生成角色卡

```
.coc     生成 COC 7 版角色卡（写入当前卡）
.coc5    生成 COC 5 版（天命）角色卡
.dnd     生成 D&D 5e 角色卡
```

⚠️ **重新生成会覆盖当前卡**（多卡场景下只覆盖切着的那张，见 5.10）。

### 5.1.1 批量掷主属性 `.coc N`（v1.4 新增）

**只掷主属性，不含任何技能与衍生值，也不写入角色卡** —— 纯给玩家挑一组用（主流骰娘同款行为）。
这也是跑团群里「天命 5 选 1」「购点前先掷几组」的标准玩法。

```
.coc 5        一次掷 5 组 COC 7 版主属性
.coc5 5       一次掷 5 组 COC 5 版（天命）主属性
.dnd 4        一次掷 4 组 D&D 5e 属性
```

输出示例：

```
🎲 COC 7 版主属性掷骰 × 5（只含主属性，技能需自行设定）
1. 力量:60 体质:65 敏捷:50 外貌:60 意志:40 体型:70 智力:70 教育:65 幸运:55 HP:13 [480/535]
2. 力量:60 体质:65 敏捷:55 外貌:35 意志:55 体型:80 智力:35 教育:75 幸运:35 HP:14 [460/495]
...
```

| 位置 | 含义 |
|------|------|
| `HP:` | 自动算好的生命值 |
| `[8项/8项+幸运]` | 前面是 8 项主属性总值（不含幸运），后面是含幸运的总值 |

- 上限 **20 组**，超出会被拒绝。
- 挑好一组后用 `.st` 批量录入（见 5.9）或按位置录入。
- **不传数字时行为不变**（`.coc` = 生成完整卡并写入），保持向后兼容。

### 5.2 COC 7 版角色卡内容

**核心属性**（3d6×5 生成）：

`力量` `体质` `敏捷` `外貌` `意志` `体型` `智力` `教育` `幸运`

**衍生值**（自动计算）：

| 衍生值 | 公式 |
|--------|------|
| 生命值 HP | `⌊(体质 + 体型) / 10⌋` |
| 魔法值 MP | `⌊意志 / 5⌋` |
| 理智 SAN | `= 意志` |
| 伤害加值 DB | 按 `力量+体型` 分档：≤64→`-2`；≤84→`-1`；≤124→`0`；≤164→`+1d4`；>164→`+1d6` |
| 体格 Build | 与 DB 同档：`-2 / -1 / 0 / 1 / 2` |
| 移动力 MOV | 力敏均 > 体型 → 9；力敏均 < 体型 → 7；否则 8 |

**技能**：48 项常用技能（会计、闪避、侦查、潜行、图书馆使用…）；

### 5.6 属性连写、增减与 HP/SAN 快捷（v1.2 新增）

**连写**：`.st` 键与值可以不空格分隔（非数字开头 + 纯数字结尾才拆分，避免误伤）：

| 紧贴写法 | 等价于 |
|----------|--------|
| `.st力量88` | `.st 力量 88` |
| `.st侦查70` | `.st 侦查 70` |

**增减**（值支持掷骰表达式，结果写回卡）：

| 指令 | 效果 |
|------|------|
| `.st hp+1` | hp 当前值 +1 |
| `.st san-1d4` | san 当前值 -1d4（掷骰） |

**HP / SAN 快捷指令**（键名优先读写卡上已有的「生命值/hp」「理智/san」）：

| 指令 | 效果 |
|------|------|
| `.hp` | 查看当前 HP |
| `.hp+3` | HP +3 |
| `.hp-1d4` | HP -1d4（掷骰） |
| `.hp 50` | HP 直接设为 50 |
| `.san-1d4` | SAN 增减（与 `.hp` 同一套语法） |

```
❤️ HP: 11 → 8（-1d4 掷出 3）
```

> 没有角色卡时使用这些指令会提示先 `.coc` 建卡或 `.st hp 50` 录入。
> 增减到负数自动归 0。

### 5.7 角色卡名字 = 玩家昵称（v1.2 新增）

`.st name <名字>`（简写 `.sn <名字>`）设置的「角色卡名字」同时就是 **bot 称呼你的昵称**：设置后，所有掷骰/检定/日志的署名、角色卡标题都会用这个名字，无需再去改平台昵称。

```
.st name 张三        →  ✅ 已设置角色卡名字（也是你的昵称）：张三
.sn 李四            →  同上，简写形式
.sn                 →  查看当前昵称
```

> 重新生成角色卡（`.coc` / `.dnd`）会**保留**已设置的昵称，不会丢失。

### 5.8 通用「紧贴写法」

**所有指令**都支持省略「动词 ↔ 参数」之间的空格（主流骰娘 / Dice! 玩家习惯），例如：

| 紧贴写法 | 等价于 |
|----------|--------|
| `.r3d100` | `.r 3d100` |
| `.ra侦查60` | `.ra 侦查 60` |
| `.st力量88` | `.st 力量 88` |
| `.boton` | `.bot on` |
| `.initadd张三 15` | `.init add 张三 15` |
| `.draw塔罗3` | `.draw 塔罗 3` |
| `.lognew黑圣杯` | `.log new 黑圣杯` |
| `.setprefix !` | `.set prefix !` |
| `.sn张三` | `.st name 张三` |

> 仅省略动词与首个参数间的空格；参数内部（如 `张三 15`、`prefix !`）仍按原样用空格分隔。

### 5.9 批量录入与「按位置」录入（v1.3 新增）

录角色卡最烦的是一条条发。`.st` 现在支持**一条消息录多个值**。

**方式一：键值批量（推荐，可读性好）**

```
.st 力量88 体质70 敏捷60 外貌75 意志80 体型65 智力70 教育60 幸运55
```

空格**可以省**，机器人靠「非数字键 + 数字值」自动切分，下面这条完全等价：

```
.st力量88体质70敏捷60外貌75意志80体型65智力70教育60幸运55
```

也可以只录一部分（未提到的属性保持原值）：

```
.st 力量88 敏捷60
```

> 单个连写 `.st 力量88` 与多个连写走的是同一条解析路径，行为完全一致。

**方式二：按位置录入（免键名）**

只给数字，机器人按**该系统的标准属性顺序**依次填入：

```
.st 88 70 60 75 80 65 70 60 55
```

各系统的属性顺序（与 `.st show` 的显示顺序一致）：

| 系统 | 顺序 | 可录数量 |
|------|------|---------|
| COC 7 版 | 力量 体质 敏捷 外貌 意志 体型 智力 教育 幸运 | 最多 9 个 |
| COC 5 版 | 力量 体质 体型 敏捷 外貌 智力 意志 教育 幸运 | 最多 9 个 |
| D&D 5e | 力量 敏捷 体质 智力 感知 魅力 | 最多 6 个 |

- 给的值可以**少于**属性总数（只填前几个），不会报错。
- 超过上限会提示改用键名写法。
- 位置录入会**覆盖**对应位置的现有值。

**怎么选？**

| 场景 | 推荐 |
|------|------|
| 从纸质卡/表格抄一整行 | 按位置录入（直接照抄数字，不用打字键名） |
| 只改几项、想留其余 | 键值批量 |
| 属性顺序记不住 | 键值批量（`.st show` 看当前值对照） |

**回复示例**

```
✅ 已按顺序录入 9 项：
力量:88  体质:70  敏捷:60  外貌:75  意志:80  体型:65  智力:70  教育:60  幸运:55
```

### 5.10 多角色卡（v1.3 新增）

一个玩家可以同时维护**多张角色卡**（不同 PC、Save 档、不同系统都行），随时切换。

| 指令 | 行为 |
|------|------|
| `.st new <标题>` | 新建一张角色卡（随机初始值）并**自动切换**过去 |
| `.st list` | 列出我的全部角色卡，`*` 标记当前卡 |
| `.st switch <标题>` | 按**名字**切换（支持部分匹配） |
| `.st switch <编号>` | 按**编号**切换（编号来自 `.st list`，从 1 开始） |
| `.st del <标题或编号>` | 删除该卡 |

**典型流程**

```
.st new 调查员A          ← 建卡并切过去
.st 88 70 60 75 80 65 70 60 55   ← 按位置录初始值
.st new 调查员B          ← 再建一张，自动切到 B
.st 力量60 体质55 ...    ← B 卡录入
.st list                 ← 看看有几张
* 1. 调查员A
  2. 调查员B
.st switch 1             ← 切回 A
.st show                 ← 确认 A 的数值还在
```

**重要语义**

| 问题 | 答案 |
|------|------|
| `.ra` / `.sc` / `.hp` 等检定读哪张卡？ | **当前卡**（`.st switch` 切到哪张就读哪张） |
| `.coc` / `.dnd` 重新生成会怎样？ | 只**覆盖当前卡**，不动其他卡 |
| `.st name` 设的昵称会丢吗？ | 不会。昵称跟着**玩家**走，所有卡通用 |
| `.st new` 的卡是什么内容？ | COC 7 版随机初始值，随后用 5.9 的批量/位置录入覆盖 |
| 删掉当前卡会怎样？ | 自动切到剩下的一张；一张都不剩则提示重新 `.coc` |

> **数据隔离**：不同玩家的卡天然隔离（按 `platform + user_id`）；同一玩家的多张卡按标题隔离，切错卡会读到另一张的数值——切换后建议 `.st show` 确认一下。

### 5.11 `.st` 属性管理完整子命令（v1.4 补齐主流骰娘语义）

| 指令 | 作用 |
|------|------|

## 六、跑团工具（奖励骰·疯狂·抽牌·名字·重排）

### 6.1 奖励骰 / 惩罚骰（`.rb` / `.rp`）

COC 7 版规则里「加骰 / 减骰」的落地实现：掷 1d100 后**额外取十位骰**做修正。

| 指令 | 行为 |
|------|------|
| `.rb 侦查 60` | 奖励骰检定：1d100 的十位 ≤ 个位时取十位作结果（更好） |
| `.rp 侦查 60` | 惩罚骰检定：十位 ≥ 个位时取十位作结果（更差） |
| `.rb` / `.rp` | 不带技能：只单独掷一次带修正的 1d100，不做技能检定 |

输出示例：

```
✅ 【张三】侦查检定(奖励骰): 1d100 = 47 / 60 → 成功
```

> 判定规则与 `.ra` 完全一致（含大成功 / 大失败），详见 [第四章](#四coc-检定ra详解)。

### 6.2 多列检定（`.ra 3#p手枪`）

一次掷多次，适合「开枪 3 发」这类场景：

```
.ra 3#p手枪      → 连发 3 次，每次带 1 个惩罚骰
.ra 5#b2侦查 55  → 连发 5 次，每次带 2 个奖励骰
.ra 4#力量       → 连发 4 次，不带修正
```

- `#` 前是次数（**上限 20**）
- `b` = 奖励骰、`p` = 惩罚骰，后跟数量（**上限 5**，不写则 1）
- 不加次数/骰种时就是普通 `.ra`

### 6.3 成长检定（`.en`）

| 输入 | 行为 |
|------|------|
| `.en 侦查` | 读取角色卡里「侦查」的当前值再掷 |
| `.en 侦查 65` | 直接指定当前值 65 再掷 |
| `.en` | 回 `用法: .en <技能名> [当前值]` |

1d100 > 当前值 → **成长 +1d10**（`Math.min(99, 当前值+1d10)`），并**自动写回角色卡**；
否则提示 `没有提升`。新手请务必先 `.st 侦查 70` 建好技能再 `.en`。

### 6.4 疯狂表（`.ti` / `.li`）

COC 7 版 1d10 表，**不需要掷骰自动出结果**，直接发指令即可：

| 指令 | 表格 | 说明 |
|------|------|------|
| `.ti` | 临时性疯狂 | 短期发作，恢复后通常无残留 |
| `.li` | 长期性疯狂 | 持久症状，需要长期处理 |

输出示例：

【惊慌逃窜】你抛下一切拼命逃离，只想离这里越远越好，甚至不惜冲进更危险的地方。
```

### 6.5 抽牌（`.draw` / `.drawlist`）

## 七、先攻管理

### 7.1 指令

| 指令 | 作用 |
|------|------|
| `.init add 张三 15` | 加入先攻（15 为先攻值） |
| `.init list` | 按先攻值**降序**查看 |
| `.init clr` | 清空当前群的先攻列表 |

### 7.2 行为细节

- **同名覆盖**：再次 `add` 同一名字会先删除旧记录再插入
- **名字可含空格**：`.init add 红龙 尼尔 20` → 名字 = `红龙 尼尔`，值 = `20`
  （取**最后一个参数**作为先攻值）
- **排序**：值高者在前；值相同按加入顺序
- **范围**：先攻列表是**群级**的，不同群互不影响；平台间也隔离

### 7.3 输出示例

`add` 成功后**直接附带列表**：

```
✅ 已加入先攻: 张三 (15)
📋 先攻顺序:
1. 李四 — 20
2. 张三 — 15
```

`list`（空列表时）：
```
📋 先攻列表为空
```

`clr`：
```
🧹 先攻列表已清空
```

### 7.4 错误处理

| 输入 | 回复 |
|------|------|
| `.init add 张三` | `用法: .init add <名字> <先攻值>\n例: .init add 张三 15` |
| `.init add 张三 abc` | `先攻值无效: abc` |
| `.init xyz` | `❓ 未知指令「init」，发送 .help 查看帮助` |

## 八、跑团日志（.log 系列）

跑完一团想留档？`.log` 会**从你按下 `.log new` 那一刻起，自动把群里发生的一切记下来**，
结束时导出成文件（QQ 风格 txt，或主流骰娘日志染色器吃的 JSON）。

### 8.1 快速开始（三句话跑通一场）

```
.log new 黑圣杯      # 新建并开始记录
... 正常跑团，群里说什么它记什么 ...
.log end             # 结束，机器人自动把文件发到群里
```

### 8.2 指令一览

| 指令 | 作用 | 权限 |
|------|------|------|
| `.log` | 看当前日志状态（名称/编号/状态/条数） | 所有人 |
| `.log new [名称]` | 新建日志并开始记录（同群同时只能有一个） | 管理员 |
| `.log on` / `.log off` | 继续 / 暂停记录（暂停期间不记，回来接着记） | 管理员 |
| `.log end [json]` | 结束记录并导出文件 | 管理员 |
| `.log get [编号] [json]` | 导出日志（不结束）。不给编号 = 当前/最后一场 | 所有人 |
| `.log list` | 列出本群最近 10 场日志（编号、状态、条数、时间） | 所有人 |
| `.log stat` | 当前日志统计（条数、参与人数、时间段、发言性质分布） | 所有人 |
| `.log del [编号]` | 删除日志（连同消息记录） | 管理员 |
| `.ob` | 切换观众模式（开启后你的发言会被标为「隐藏」） | 所有人 |

**无空格写法**（v1.1.0 补的，参考图里用的是这种）：
`.lognew` ≡ `.log new`、`.logon` ≡ `.log on`、`.logoff` ≡ `.log off`、`.logend` ≡ `.log end`、
`.loglist`、`.logget`、`.logdel`、`.logstat`。

### 8.3 记录什么 / 不记录什么

| 内容 | 记录形式 |
|------|----------|
| 普通文字 | 原文 |
| @某人 | `@名字` |
| 图片 | `[图]` |
| 表情 | `[表情]` |
| 语音 | `[语音]` |
| 回复 | `[回复]` |
| 骰子输出 | 正常文本，并在 JSON 里标 `isDice:true`（主流骰娘语义） |
| 场外 | 以 `(`、`（`、`【` 开头的发言 |
| 指令 | 以 `.` `。` `/` 开头的发言（`.` 开头后跟 `.` `/` 的不算） |
| 观众模式发言 | 前缀 `[OB]`，导出后可直接剔除 |

> **只在群里记录**，私聊发 `.log` 会提示「跑团日志只能在群里使用」。
> **机器人自己的消息不会被重复记录**（按 `selfId` 过滤），避免日志里每条回复都夹一层。
> 没有进行中的日志时 `capture()` 直接返回，**零写库开销**，不影响非跑团群。

### 8.4 导出的两种格式

| 参数 | 文件 | 用途 |
|------|------|------|
| 不带参数 | `<名称>-<编号>.txt` | QQ 风格文本，条头 + 正文，可直接存档 / 贴进染色器 |
| `json` / `js` / `json格式` | `<名称>-<编号>.json` | 主流骰娘（跑团日志染色器）格式，可导入后自动上色 |

条头格式（txt）：

```
【条头】名字(账号) 2026/10/02 21:08:00(#12)
【正文】@张三 我检查了一下门把手 → [图]
【场外】(等等，我刚才是不是说漏了)
```

导出文件写在 `ALEABOT_LOG_DIR`（默认 `./data/logs`，生产环境 `<安装目录>/data/logs`），
机器人会尝试用 `upload_group_file` 把文件**直接传进群**；平台不支持时降级成「把前 60 行文本发出来」，
绝不会出现「什么都没拿到」。

### 8.5 观众模式（`.ob`）

主持人 / 水友想全程插话但不污染剧情记录时：

```
.ob   → 开启：之后你的发言全部带 [OB] 前缀
.ob   → 关闭：恢复正常
```

配合 `.log end json` 导入染色器，可以按 `[OB]` 一键剔除所有观众插话。

### 8.6 权限说明（重要）

`new / on / off / end / del` 归管理员；`list / get / stat / .log 状态` 所有人可用。

> ⚠️ **刻意设计**：如果 `.env` 里 `ADMIN_IDS` 是空的（默认），则不限制 —— 所有人都能开日志。
> 一旦配置了 `ADMIN_IDS`，就严格只认管理员。**没配管理员却建不了日志，属于配置问题，不是 bug**。

### 8.7 存储

两张表，跑团数据不与他人混淆（按 `(platform, group_id)` 隔离）：

| 表 | 用途 |
|----|------|
| `log_sessions` | 一场日志：编号、平台、群、名称、状态（recording/paused/ended）、创建人、时间 |
| `log_messages` | 每条记录：所属日志、发言人、类型（chat/dice/ooc/command/image）、正文、是否骰点、角色 |

> 跑团日志**独立于**掷骰日志表 `logs`（那张表是 `.r/.ra/.stat` 用的），两者互不干扰。

## 九、管理员指令

### 9.1 管理员的定义

在 `<安装目录>/.env` 中配置：

```env
ADMIN_IDS=2749353602,940129350
```

- 多个用**英文逗号**分隔
- QQ 平台填 **QQ 号**；KOOK 平台填 **KOOK 用户 ID**
- 不区分平台——同一个 ID 列表同时作用于 QQ 和 KOOK

修改后需 `sudo systemctl restart aleabot` 生效。

### 9.2 `.set` — 群配置

| 指令 | 作用 |
|------|------|
| `.set prefix !` | 把本群指令前缀从 `.` 改为 `!` |
| `.set defaultDice 1d20` | 把本群默认骰从 `1d100` 改为 `1d20` |

**可用配置键（仅两个）**：

| 键 | 含义 | 默认值 |
|----|------|--------|
| `prefix` | 指令前缀 | `.` |
| `defaultDice` | `.r` 无参数时用的骰子 | `1d100` |

**关于前缀的补充**：

- 前缀为 `.`（默认）或 `。` 时，**英文句点与中文句号互认**，两种都能触发指令。
- 改成其他字符（如 `!`）后，只认那个字符，`.` 和 `。` 都不再是前缀。

**行为细节**：

- 配置**按群隔离**（`platform + group_id` 维度），改 A 群不影响 B 群
- 值可以含空格：`.set defaultDice 2d6+1` → 值为 `2d6+1`
- 非允许键：`不支持的配置键: xxx（可用: prefix, defaultDice）`
- 非管理员：`⛔ 只有管理员可以修改群配置`
- 参数不足：`用法: .set <键> <值>\n可用键: prefix(指令前缀), defaultDice(默认骰)`

**⚠️ 改前缀后的注意点**：改完 `.set prefix !` 后，`.set` 本身就失效了，
后续必须用 `!set prefix .` 才能改回来。

### 9.3 `.bak` — 手动备份

| 场景 | 行为 |
|------|------|
| **管理员私聊**发送 `.bak` | 执行备份，回复文件路径到私聊 |
| **管理员在群里**发送 `.bak` | 执行备份，**私聊**回复（不刷屏） |
| 非管理员发送 | `⛔ 只有管理员可以执行备份` |

回复格式：
```
💾 备份完成: <安装目录>/data/backups/aleabot-backup-2026-10-02T08-30-00-000Z.db
```

### 9.4 管理员能力汇总

| 能力 | 入口 |
|------|------|
| 修改群配置（前缀、默认骰） | `.set` |
| 手动备份数据 | `.bak` |
| 网页后台全部操作 | `http://<服务器IP>:8787/` |

### 10.3 后台 API 一览

所有接口均需通过 `?token=` 或 `X-Admin-Token` 头鉴权（若配置了口令）。

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/status` | 运行状态（平台、统计、备份信息、数据库路径） |
| GET | `/api/logs` | 掷骰日志。参数：`platform` `groupId` `userId` `keyword` `limit`(≤500) `offset` |
| GET | `/api/sheets` | 角色卡列表（含属性摘要）。参数：`platform` |

| GET | `/api/settings` | 群配置查询。参数：`platform`（默认 qq）`groupId` |
| POST | `/api/settings` | 群配置修改。Body：`{platform, groupId, key, value}` |
| GET | `/api/backups` | 备份文件列表（名称、大小、时间、路径） |
| POST | `/api/backups` | 立即生成一份备份 |
| GET | `/api/backups/download/:name` | 下载指定备份文件 |
| GET | `/api/export` | 导出全部数据为 JSON（含 logs/sheets/settings/initiative） |
| POST | `/api/send` | 向指定群**主动发消息**（调试用）。Body：`{platform, groupId, text}` |
| GET | `/api/help-image` | 读取当前 `.help` 用的指令图（返回 `{path, exists, width, height}`） |
| POST | `/api/help-image` | 替换指令图。Body：`{dataUrl}`（base64 DataURL，**上限 2 MB**） |
| POST | `/api/help-image/reset` | 恢复为内置默认指令图 |

**常用 curl 示例**：

```bash

# 立即备份
curl -X POST "http://<服务器IP>:8787/api/backups?token=你的口令"

# 主动向群发消息（调试）
curl -X POST http://<服务器IP>:8787/api/send \
  -H "Content-Type: application/json" \
  -d '{"platform":"qq","groupId":"1048322583","text":"机器人上线测试"}'
```

## 十一、数据与备份

### 11.1 文件位置

| 内容 | 路径 |
|------|------|
| 数据库 | `<安装目录>/data/aleabot.db` |
| WAL 日志 | `<安装目录>/data/aleabot.db-wal` |
| 共享内存 | `<安装目录>/data/aleabot.db-shm` |
| 备份目录 | `<安装目录>/data/backups/` |
| 应用日志 | `<安装目录>/logs/bot.log` |
| 错误日志 | `<安装目录>/logs/bot.err.log` |

### 11.2 数据库表结构

| 表 | 内容 | 唯一约束 |
|----|------|----------|
| `sheets` | 角色卡 | `(platform, user_id)` |
| `bindings` | 群与用户绑定（预留扩展） | `(platform, group_id, user_id)` |
| `settings` | 群级配置键值对 | `(platform, group_id, key)` |
| `initiative` | 先攻列表 | 无（同名由应用层覆盖） |
| `logs` | 掷骰日志主表 | 无 |
| `log_lines` | 日志明细（骰子组） | 外键 → `logs(id)` 级联删除 |
| `meta` | 元信息（schema 版本、备份时间） | `key` |

数据库使用 **WAL 模式** + `busy_timeout = 5000`，兼顾并发读写与备份安全性。

### 11.3 三重备份保护

| 机制 | 触发时机 | 默认参数 |
|------|----------|----------|
| **自动备份** | 每 N 小时；且启动时若当天没备份过会立即补一次 | 每 24 小时 |
| **退出保护** | 进程收到 SIGTERM / SIGINT 时 | 每次停止都备份 |
| **手动备份** | 后台「立即备份」按钮，或管理员 `.bak` | — |

**保留策略**：只保留最近 **14** 份，更早的自动删除。

**可调参数**（`.env`）：

```env
BACKUP_INTERVAL_HOURS=24    # 备份间隔（小时），设为 0 关闭自动备份
BACKUP_KEEP=14              # 保留份数
```

### 11.4 恢复数据

```bash
# 1. 停止服务（停止时会自动备份当前数据，多一层保险）
sudo systemctl stop aleabot

# 2. 用备份覆盖主库
sudo cp <安装目录>/data/backups/aleabot-backup-2026-10-02T08-30-00-000Z.db \
        <安装目录>/data/aleabot.db

# 3. 删掉 WAL / SHM 残留（关键！不删会读到旧数据）
sudo rm -f <安装目录>/data/aleabot.db-wal <安装目录>/data/aleabot.db-shm

# 4. 启动
sudo systemctl start aleabot
```

### 11.6 迁移到新机器

1. 拷走 `<安装目录>/data/aleabot.db`（或任一份备份）

## 十三、故障排查

### 13.1 排查流程图

```
机器人不回复
    │
    ├─ 1. systemctl status aleabot  → 服务在跑吗？
    │       └─ 没跑 → journalctl -u aleabot -n 50 看错误
    │
    ├─ 2. tail <安装目录>/logs/bot.log
    │       ├─ 有 [adapter] qq 已连接 → 连接正常，进第 3 步
    │       └─ 无「已连接」→ 查 NapCat（第 11.3 节）
    │
    ├─ 3. 群里发 .help，看日志有没有 "[msg] 收到"
    │       ├─ 没有 → 消息没到机器人
    │       │        → NapCat 掉线？群被屏蔽？机器人被禁言？
    │       └─ 有，但显示「无回复」→ 前缀不对？
    │                → 试 .set 查后台配置，或直接发 .help
    │
    └─ 4. 有「已回复」但用户没收到 → 发送失败
            → 机器人被禁言 / 被踢 / 消息含敏感词
```

### 13.2 常见问题速查

**Q1：机器人不回复**

```bash
# 第 1 步：查 AleaBot 日志
tail -30 <安装目录>/logs/bot.log
```
- 无 `[adapter] qq 已连接` → 见 Q2
- 有连接但无 `[msg] 收到` → QQ 消息没进来，见 Q4
- 有 `[msg] 收到` 但无 `[msg] 已回复` → 前缀不对，或消息不含指令

**Q2：AleaBot 连不上 NapCat**

```bash
# 确认 NapCat 在跑
systemctl status napcat

# 确认 3001 端口在监听
ss -tlnp | grep 3001

# 确认 .env 配置
grep ONEBOT <安装目录>/.env
```

正常情况下应为：
```env
ONEBOT_ENABLED=true
ONEBOT_WS_URL=ws://127.0.0.1:3001
ONEBOT_TOKEN=
```

若 NapCat 侧设置了 token，`.env` 的 `ONEBOT_TOKEN` 必须一致，否则握手失败。

**Q3：QQ 掉线 / 要求重新登录**

1. 浏览器打开 `http://<服务器IP>:6098/`（实时二维码页，每 5 秒自动刷新）
2. 手机 QQ 扫码登录
3. 若 WebUI token 变了，从 `<NapCat目录>/app/runtime/config/webui.json` 读最新 token

> ⚠️ 二维码**每 2 分钟自动刷新**，所以永远不要「截图转发」二维码——必然过期。
> 一定要用 `6098` 这个实时页面。

**Q4：NapCat 在跑、AleaBot 也连着，但消息收不到**

```bash
# 看 NapCat 有没有收到 QQ 消息
tail -20 <NapCat目录>/logs/napcat.log | grep -E '接收|发送'
```

- 有「接收」→ 消息到了 NapCat，问题在 WS 转发：检查 `websocketServers` 配置
- 无「接收」→ QQ 侧问题：机器人在这个群吗？被禁言吗？

**Q5：掷骰结果不符合预期**

| 症状 | 原因 |
|------|------|
| `4d6k3` 结果看着偏小 | `k3` = 保留**最高** 3 个，不是最低 |
| 想取低却用了 `k` | 取低要用 `kl`，如 `2d20kl1` |
| 表达式报「无法识别的项」 | 检查是否写了 `x` 号（应该用 `d`），或含中文标点 |

**Q6：`.ra 侦查` 提示未找到目标值**

角色卡里没有「侦查」这个键。两种情况：
- 没生成过角色卡 → 先 `.coc`
- 生成了但技能基础值太低没被列出 → 直接 `.ra 侦查 60` 手动给值

**Q7：`.set` 说我不是管理员**

```bash
grep ADMIN_IDS <安装目录>/.env
```
把 QQ 号加进 `ADMIN_IDS`（英文逗号分隔），然后 `sudo systemctl restart aleabot`。

**Q8：网页后台打不开**

```bash
# 确认端口在监听
ss -tlnp | grep 8787

# 确认服务在跑
systemctl status aleabot

# 从本地测试
curl http://127.0.0.1:8787/api/status
```
若配了 `ADMIN_TOKEN`，记得 URL 带 `?token=xxx`。

**Q9：改端口**

`.env` 中 `WEB_PORT=8787`，改完 `sudo systemctl restart aleabot`。

**Q10：忘记后台口令**

```bash
grep ADMIN_TOKEN <安装目录>/.env
```
或删掉该行清空口令（不建议公网环境这么做）。
